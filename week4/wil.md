#  동시성 제어
  ### 영속성 컨텍스트
      : 영속성 컨텍스트에서는 데이터베이스에서 조회한 엔티티를 트랜잭션 동안 관리한다.
        엔티티를 조회하여 주문 수량의 변경이 감지되면 UPDATE SQL이 실행된다. 

  ### 갱신 손실
      : 여러 주문이 동시에 들어오면 주문 한 개를 제외한 나머지 주문이 누락되어 손실이 발생한다.

  ### 낙관적 락
      : 충돌이 자주 일어나지 않을 경우 트랜잭션의 version을 저장하여 충돌을 확인한다. 
        트랜잭션이 먼저 완료되면 version을 증가시키고, 그 다음 트랜잭션에서 version을 비교하여 다를 경우 예외 처리한다.

      - 동시 주문 테스트 결과 성공=1, 실패=9, 최종 재고=4
      - 실패한 원인은 10개의 주문이 들어왔을 때 맨 처음 주문만 처리되고 나머지는 version이 달라졌기 때문이다.

  ### 비관적 락
      : 충돌이 자주 일어날 경우 트랜잭션을 잠금하고 순차적으로 처리한다.
        하나의 트랜잭션이 처리하는 동안 다른 트랜잭션은 대기한다.
        
  ### 낙관적 락 재시도
      - 낙관적 락 충돌 시 예외를 감지하여 재시도하도록 처리할 수 있다. 
        @Retryable 어노테이션을 사용하여 재시도 동작을 처리하거나 지연/분산 처리를 통해 충돌을 방지한다.

      - 재시도가 늘어날수록 사용자 응답 시간이 길어지므로 약 1초~2초 이내에 응답이 나가야 한다.
        따라서 재시도 횟수를 2~3회 내로 한정해야 한다.

  ### 낙관적 락 vs 비관적 락
      - 낙관적 락은 충돌이 자주 일어나지 않을 경우 사용하고, 비관적 락은 자주 발생할 때 사용한다.
      - 낙관적 락은 작업 후 충돌을 확인하고, 비관적 락은 조회 시점부터 잠금한다.
      - 낙관적 락은 트랜잭션 대기 시간이 없지만, 비관적 락은 락을 획득할 때까지 대기해야 한다.
