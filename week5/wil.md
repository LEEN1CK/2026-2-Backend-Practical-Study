### Fetch Join
    : join 쿼리를 발생시켜 OrderItem을 한 번의 SQL 쿼리로 동시조회한다. 
    단 하나의 결과 집합을 생성하여 한 번에 가져오므로 데이터 양과 상관없이 SQL 개수는 항상 1회이다.
    SQL 개수: 10건 - 1개, 20건 - 1개

### Batch Size
    : 지연로딩(LAZY) 시 연관된 엔티티를 매번 개별 쿼리로 가져오는 대신에 Batch Size만큼 묶어서 조회한다. 
    주문 수가 20건으로 늘어남에 따라 10개씩 묶는 IN절 쿼리가 1회 추가되어 3개가 발생한다.
    SQL 개수: 10건 - 2개, 20건 - 3개

### Fetch Join의 한계
    : 데이터가 수만 건 이상일 경우 메모리 오류가 발생하여 서버가 다운될 수 있다.
    한 엔티티 내에서 둘 이상의 컬렉션을 동시에 Fetch Join;하면 카타시안 곱에 의해 데이터가 폭발적으로 증가하게 된다.

### Batch Size의 장점
    : 부모 엔티티에 대해 정해진 한계 내에 속한 N개의 부모 ID만 IN절로 가져오기 떄문에 메모리 낭비가 없다. 
    여러 개의 컬랙션 관계가 존재해도 안전하게 묶어서 가져올 수 있다. 

### Query Tuning
    : 데이터베이스 연산 자원의 불필요한 소비를 줄이고 SQL의 응답 시간과 시스템 처리량을 최적화하는 작업이다.
    해결할 수 있는 문제
    1. 서버 CPU 및 Disk 병목 현상 제거
    2. 대용량 데이터 조회 시 발생하는 슬로우 쿼리 개선
    3. 서비스 사용자의 응답 대기 시간 단축

### 그 밖에 SQL 개수를 줄이는 요소
    : 내부 작업 절차를 분석하여 병목 지점을 찾아낸다.
    인덱스를 활용하여 탐색 효율을 높인다.
    불필요한 컬럼을 제거하여 데이터 전송량을 높이고 대량 데이터 조회 시 한 번에 읽어오는 행의 수의 상한을 제한한다.
