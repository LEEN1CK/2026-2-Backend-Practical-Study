
## 1. Service 계층의 분리
    Controller-Service-Repository 아키텍쳐 환경에서는 대부분의 비즈니스 로직이 Service에 집중되는 문제가 있다.

  ### AS-IS 문제점
    - @Setter의 무분별한 사용으로 엔티티 상태를 외부에서 자유롭게 변경할 수 잆는 우회로가 생긴다.
    - 동일한 검증이 중복해서 발생한다.
    - 요구사항이 변경되었을 때 수정을 반복해야 한다.

  ### TO-BE: Tell, Don't Ask
    - 엔티티에서 @Setter를 없애 우회로를 막는다.
    - 데이터 변경, 검증을 엔티티 내부 매서드에서 처리하게 한다.

## 2. 테스트 코드 기반의 Refactoring
    수동 테스트(Postman, Swagger)에 의존하는 대신 자동화된 테스트 코드를 통해 안전하게 검증한다.

  ### 단위 테스트 vs 통합 테스트
    - 단위 테스트: 작은 단위의 동작을 독립적을 비교적 빠르게 검증한다.
    - 통합 테스트: 여러 구성 요소 간의 연동을 확인한다.

  ### 테스트 작성 도구
    - JUnit 5: @Test으로 테스트 대상을 식별하고 실행한다.
    - AssertJ: assertThat()을 통해 테스트 검증문의 가독성을 높인다.
    - Given: 테스트를 수행하기 위한 길초 환경 및 상태를 준비한다.
    - When: 검증하고자 하는 행위를 실제로 수행한다. 
    - Then: 수행 결과가 기대한 상태와 일치하는지 표현한다.
